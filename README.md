# Watermelon

Watermelon combines a Telegram userbot (Telethon, running as your Telegram account) with a separate BotFather bot (aiogram). The userbot can import accessible text history from a chat you explicitly select, store new incoming text messages, and let the separate bot analyze stored messages.

## Privacy and security

- Never publish `TG_SESSION`, `TG_API_HASH`, `LLM_API_KEY`, or `BOT_TOKEN`. The session string grants access to your Telegram account.
- Create the userbot session on your own computer and add it to Render only through **Environment**.
- Import history only from chats where you have permission to process the messages. Use `.sync` in the specific chat instead of indiscriminately importing every conversation.
- Only text messages and text captions are stored; this is not a complete copy of every Telegram data type.
- Telegram access is limited to the chats and history available to your account.
- Model output may be inaccurate and should not be treated as a diagnosis or definitive judgment about a person.

## 1. Telegram API credentials and session

1. Open https://my.telegram.org and sign in.
2. Open **API development tools** and get `api_id` and `api_hash`.
3. Install Python 3.12+ and dependencies locally, then create a session:

```bash
pip install -r requirements.txt
python -m app.create_session
```

Keep the generated session string private.

## 2. Render Web Service

Create or open a **Web Service** connected to this repository.

**Build Command**
```bash
pip install -r requirements.txt
```

**Start Command**
```bash
python -m app.web
```

The `app.web` entry point binds an HTTP health endpoint to `0.0.0.0:$PORT` for Render and runs both the existing bot and userbot concurrently.

## 3. Environment variables

Add these under Render → **Environment**:

- `BOT_TOKEN` — token for the existing BotFather bot.
- `TG_API_ID` — API ID from my.telegram.org.
- `TG_API_HASH` — API hash from my.telegram.org.
- `TG_SESSION` — session string generated by `python -m app.create_session`.
- `LLM_BASE_URL` — `https://generativelanguage.googleapis.com/v1beta/openai/`.
- `LLM_API_KEY` — API key for the configured Gemini-compatible endpoint.
- `LLM_MODEL` — defaults to `gemini-2.5-flash`.
- `DATABASE_PATH` — defaults to `messages.db`.
- `MAX_MESSAGES_PER_ANALYSIS` — defaults to `100`.
- `MAX_MESSAGES_PER_SYNC` — defaults to `5000` most recent messages for each explicit sync.

The combined Web Service requires both the bot token and the userbot credentials. The userbot by itself does not require `BOT_TOKEN`, but the existing bot component does.

## 4. Import history and analyze it

1. Open the group or chat using your personal Telegram account.
2. Send `.sync` from your account in that chat. Watermelon imports up to `MAX_MESSAGES_PER_SYNC` recent messages available to your account and avoids duplicating messages already stored.
3. Open the separate BotFather bot and send `/analyze USER_ID` to analyze that user's stored messages across synced chats.
4. To restrict analysis to one chat, send `/analyze CHAT_ID USER_ID`.

Userbot commands (sent from your own account):

- `.sync` — import recent accessible history for the current chat.
- `.analyze USER_ID` — analyze accessible history in the current chat.
- `.analyze` — in a private chat, analyze the conversation partner.
- `.analyzeall USER_ID` — analyze stored messages for a user across synced chats.
- `.helpwatermelon` — show userbot help.

The userbot also stores new incoming text messages after startup. History synchronization is explicit per chat; it does not automatically import every private conversation or group.

## 5. Health check and storage

- Health endpoint: `/health`.
- Render's local filesystem may not persist across service replacement or redeployment. For durable SQLite storage, configure a persistent disk or move to an external database.
